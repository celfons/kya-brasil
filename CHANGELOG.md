# Changelog

## Unreleased

- **Cloud e-CNPJ through an interface (D-28).** `@kya-brasil/core` 0.9.0: `CloudSignatureProvider` (OAuth authorization code with PKCE; session with `certificates()` and `signHash`), `cloudSigner`, `pkcePair`, `newState`, `isProviderId`. Three entry points: the library; `kya-sign --cloud <module> [--port] [--no-open]` in `@kya-brasil/agent-tools` 0.9.0 (browser approval, one-time redirect on 127.0.0.1); and on a self-hosted issuer the `/sign` page's "Certificado em nuvem" tab with `GET /sign/cloud/{provider}/start` and `GET /sign/cloud/callback` (single-use state in KV for 10 minutes, provider session only during the callback, only the stored challenge is signed). No PSC is implemented: template in `examples/cloud-provider`; providers are registered in `apps/worker/src/cloud-providers.ts` (empty on the reference issuer). `/status` lists `cloud_providers`. Tested end to end against a fake PSC over HTTP (terminal and page, credential issued). Issuer 0.10.0.
- **A1 and A3 everywhere (D-27).** e-CNPJ signing moved into `@kya-brasil/core` 0.8.0: `buildDetachedCms` (any signer that signs bytes: PKCS#11 token, HSM, cloud), `ecnpjSigner`, `openPfx` / `signWithECnpjPfx` (now async), `signingLink` / `readSigningLink`. npm client 0.8.0 depends on the core and re-exports them; adds `openToken` / `listTokenCertificates` (PKCS#11 through the optional `pkcs11js`), `kya-sign --pkcs11 <library> [--list] [--label] [--slot]` with the PIN from `KYA_TOKEN_PIN` or a prompt, and `kya.signLink`. Server: free `kya_sign_link` (MCP) and `GET /v1/agents/{id}/sign-link` return the signing link with the agent's signature, built by the core. CI installs SoftHSM2 so the token path is tested on every push; tested locally end to end (token → `kya-sign --link` → credential issued). Issuer 0.9.0.
- **Signing with the e-CNPJ without code (D-26).** `GET /sign`: page for the e-CNPJ holder, opened from the new `sign_url` in the registration response (the agent appends `&agent_signature=`). Shows company, agent, issuer, expiry and the requested mandate; warns on another issuer or an expired challenge; signs in the browser with an A1 `.pfx`/`.p12` (node-forge pinned by SRI, strict CSP with nonce, no referrer; nothing leaves the browser) or takes a `.p7s` from any ICP-Brasil signer over the downloaded challenge (A3 tokens, cloud certificates); then issues. Pending credentials show `requested_mandate` at `GET /v1/agents/{id}`. npm client 0.7.0: `signWithECnpjPfx` and `openPfx` (legacy 3DES/RC2 PKCS#12 included), `signingLink`, and the `kya-sign` command. Tested end to end in Chromium with a test ICP chain and CRL, both paths. Issuer 0.8.0.
- **Security fix:** an attached CMS signature (the `.p7s` carries the signed text) was verified over its own content, so any document a company ever signed with its e-CNPJ passed as consent to any challenge, revocation or company request. The embedded content must now equal the challenge byte for byte; detached signatures are unchanged. Issuer 0.7.1, `@kya-brasil/core` 0.7.1.
- **Payment instruments and the core library (D-25).** Mandates accept `payment_instruments` (`{ network, ref_sha256, label? }`, SHA-256 of a network token reference or PAR, never a card number; card numbers, long digit runs in labels, unknown fields and duplicates are refused). `/v1/agents/{id}/allowed` and `kya_check_action` take `payment_network` and `payment_ref_sha256`, evaluate them and echo them in the signed verdict. `packages/core` is now the public npm library `@kya-brasil/core` 0.7.0 (was the private `@kya-br/core`): e-CNPJ and ICP-Brasil validation, CRL revocation, agent signatures, mandate evaluation, credential build, signing and verification, plus `hashPaymentRef`; ESM with `.js` imports, works in plain Node. `buildCredential` no longer requires `kyb`. npm client 0.6.0: `hashPaymentRef`, payment fields in `ActionQuery` and tool schemas, local `checkMandate` evaluates `payment_instruments` and `max_per_day` (with `spent_today`). Issuer 0.7.0.
- **Registration check optional and non-blocking (D-24):** `REGISTRATION_CHECK=off` skips it (`registration_status: NOT_CHECKED`); with every source down the credential is issued as `UNVERIFIED`. Both carry the reason in the new `warnings` field of the issuance response (also in `kyb_warnings`). Only a confirmed status other than ATIVA refuses issuance; the daily review ignores unknown answers. `/status` shows `registration_check`; the landing page shows the sources again. Issuer 0.6.1, npm client 0.5.4.
- **No KYB dependency (D-23):** the KYB Brasil client, the `KYB` service binding and `KYB_INTERNAL_KEY`, `KYB_URL`, `REGISTRATION_SOURCE` are gone. Registration status comes from the Receita's open data (BrasilAPI, CNPJ.ws), optionally after an own endpoint in `CNPJ_API_URL` (BrasilAPI format, `{cnpj}` placeholder). `/status` reports `registration_sources` instead of `registration_source` and `kyb_channel`. Kept for /v1: `kyb_snapshot` (always `null`), `kyb_warnings` (always empty), error code `KYB_BLOCKED`. Issuer 0.6.0, npm client 0.5.3 (types and description).
- Registration price lowered from $0.50 to $0.25 (D-22). npm client 0.5.2 carries the new price in its hints and README.
- npm client 0.5.1: relative imports carry the `.js` extension, so the package loads in plain Node ESM (0.3.0 to 0.5.0 failed with `ERR_MODULE_NOT_FOUND` outside bundlers).
- Container for evaluation: `docker compose up` runs the issuer on `workerd` with D1, KV and the Durable Object emulated in a volume, public registration source, Base Sepolia, anchors from the repository, signing key generated once (`docker/`, `docker-compose.yml`). `/status` now reports the number of ICP-Brasil anchors loaded.
- Landing page at `/` for browsers (Accept negotiation; agents and curl keep the JSON index): live figures from `/status`, tools and prices, links to Swagger, llms.txt, MCP, npm, GitHub and the spec.
- **0.5.0, acts removed (D-19):** `POST /v1/agents/{id}/acts`, `GET /v1/acts/{act_id}`, the act text and export routes, the MCP tools `kya_register_act`, `kya_act`, `kya_act_text`, `kya_acts_export` and the client's `registerAct`, `act`, `actText`, `exportActs`, `actsExportText` are gone; migration `0005` drops the `acts` table. `max_per_day` is evaluated with the caller's `spent_today`; `/allowed` keeps `spent_today_registered: null`.
- Company inventory and webhooks (D-20): `POST /v1/companies/{cnpj}/agents` and `/webhook` (free, e-CNPJ-signed, `at:` within 10 minutes), MCP `kya_company_agents` and `kya_company_webhook`, client `companyAgents`, `setCompanyWebhook`, `companyText`. Signed events: credential issued, renewed, suspended, reinstated, revoked (lifecycle only, never what the agent does). Spec section 13 rewritten.
- Availability (D-21): `/status` shows the last daily review; client `verifyCredentialOffline` (signature and `expires_at`, `live_status: "unknown"`); terms and `llms.txt` state what an offline check proves. npm client 0.5.0.
- Security hardening from SonarCloud: GitHub Actions pinned by commit SHA; Pulumi CLI and mcp-publisher installed at pinned versions with SHA-256 verification (no more `curl | sh`, HTTPS enforced with `--proto '=https' --tlsv1.2`); `smoke.mjs` accepts only an exact host allowlist (localhost or `SMOKE_ALLOWED_HOSTS`, which the CD sets to the host it deployed) and builds URLs with `new URL()`; `demo-gif.py` takes an output name and writes under `./out`; `registry-version.mjs` accepts only relative paths inside the working directory.
- `.github/dependabot.yml`: weekly grouped updates for the SHA-pinned GitHub Actions.
- npm client: counterparty matching in `checkMandate` no longer uses a backtracking regex (a crafted counterparty took ~22 s; now linear). Base64url padding trimmed without regex in core and client. Canonical JSON keeps its exact key order through an explicit code-unit comparator. One base64url helper in the client (`src/base64url.ts`).

## 0.4.0

- npm package published with provenance and mirrored to GitHub Packages as `@celfons/kya-agent-tools` (repository page, Packages).
- Scope (D-15): the issuer attests the link between agent and company. Issuance and status depend only on the e-CNPJ (valid, not revoked) and the company being ATIVA at the Receita Federal; sanctions, forced labour, debt and risk score no longer deny or suspend a credential. `kyb_snapshot` stays in v1 credentials as information. The daily review reads only the registration status from KYB Brasil and lifts suspensions made under the old rules when the company is ATIVA.
- e-CNPJ revocation (D-16): the certificate is checked against its AC's CRL at issuance, renewal and acts export (fail closed, new errors `CERTIFICATE_REVOKED` 422 and `REVOCATION_UNAVAILABLE` 502), and every day after: revoked → credential revoked; on hold → suspended; replaced or retired after the authorization → unchanged. CRLs cached in KV until nextUpdate (6 h at most). Migration `0004` stores the serial number, the issuing AC's certificate and the CRL URLs (public data, no CPF). Spec sections 4, 6 and 11.
- The review no longer reinstates ERC-8004 credentials suspended for a wallet change.
