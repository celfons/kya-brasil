## 0.4.0

- npm package published with provenance and mirrored to GitHub Packages as `@celfons/kya-agent-tools` (repository page, Packages).
- Scope (D-15): the issuer attests the link between agent and company. Issuance and status depend only on the e-CNPJ (valid, not revoked) and the company being ATIVA at the Receita Federal; sanctions, forced labour, debt and risk score no longer deny or suspend a credential. `kyb_snapshot` stays in v1 credentials as information. The daily review reads only the registration status from KYB Brasil and lifts suspensions made under the old rules when the company is ATIVA.
- e-CNPJ revocation (D-16): the certificate is checked against its AC's CRL at issuance, renewal and acts export (fail closed, new errors `CERTIFICATE_REVOKED` 422 and `REVOCATION_UNAVAILABLE` 502), and every day after: revoked → credential revoked; on hold → suspended; replaced or retired after the authorization → unchanged. CRLs cached in KV until nextUpdate (6 h at most). Migration `0004` stores the serial number, the issuing AC's certificate and the CRL URLs (public data, no CPF). Spec sections 4, 6 and 11.
- The review no longer reinstates ERC-8004 credentials suspended for a wallet change.

## 0.3.0

- Mutual authentication: signed responses bound to the request (`signResponse`, `verifyResponse`, `createKyaAgent().fetch`), spec section 14.1. Client 0.4.0.
- "Sign in with KYA": request signing profile (spec section 14) and `createKyaAuth` in the npm package (0.3.0) with Hono, Express and fetch-handler adapters, credential cache, local mandate check and issuer verdict.
- Acts: `POST /v1/agents/{id}/acts` ($0.02, MCP `kya_register_act`) registers what the agent did, re-checks the mandate with everything registered today (daily ceilings across counterparties), records denied acts as evidence and returns a signed receipt; `GET /v1/acts/{act_id}`, act text for the optional agent signature, and the company's trail export signed with the e-CNPJ. `/allowed` now uses the registered total too (`spent_today_registered`). Spec section 13.

## 0.2.0

- ERC-8004 identities (read-only): agent kind `erc8004`, wallet resolved on chain (Base, Ethereum and their testnets by default; `EVM_RPC_URLS` to add chains) at registration, proof and daily review; credentials carry `agent.wallet`.
- Open source under MIT: LICENSE, SECURITY.md, CONTRIBUTING.md; specification `docs/SPEC.md` with test vectors.
- Examples fixed: `max_per_operation` and `max_per_day` are `{ amount, currency }`, as the schema says.
- npm package `@kya-brasil/agent-tools` (client, signing helpers, adapters) with a manual publish workflow.
- MCP server (streamable HTTP at `/mcp`, one Durable Object per session) with the same tools as the HTTP API and x402 inside the protocol; `/server.json` and `/icon.svg`; automatic publication to the MCP Registry from the prod CD; optional Glama claim at `/.well-known/glama.json`.
