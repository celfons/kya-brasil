Causes checked by hand:

- `@peculiar/x509` 2.1.0 is what `@kya-brasil/core` up to 0.19.0 used. Its `X509Crl` parses through asn1js, whose default limit of 10 000 nodes refuses every CRL above about 1 240 entries; PKI.js parses with the same asn1js. Its `verify({ publicKey: X509Certificate })` takes the hash from the certificate's own signature algorithm, not the CRL's: AC SOLUTI RFB v1's CRL (sha256WithRSAEncryption) under a certificate signed with SHA-512 gives `false`, and `true` with a key imported for SHA-256. For Ed448 it also returns `false` instead of reporting the algorithm as unsupported, so a verifier cannot tell it from a forgery.
- AC Raiz v4's key is brainpoolP512r1 written with explicit curve parameters; only OpenSSL maps them to the named curve. Web Crypto has no Brainpool curve, so the core refuses it as unsupported (REVOCATION_UNAVAILABLE).
- 1.3.6.1.4.1.44588.2.1 is id-Ed521: PureEdDSA with SHAKE256 over the E-521 curve, adopted by ITI in DOC-ICP-01.01. It has no IETF specification, and none of the libraries here implements it.
- Node 22 marks Ed448 in Web Crypto as experimental and prints a warning.
